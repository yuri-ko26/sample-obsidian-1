# プロンプトログ運用ルール

## 目的
生成AI提供元からログ取得ができない前提でも、**自己記録によって「いつ・誰が・何を・どのツールで生成したか」を説明できる状態**を維持する。

## 記録タイミング
- 1生成ジョブ（1回の実行）につき1レコード
- 採用/不採用にかかわらず、**クライアント案件に関わる生成はすべて記録**（不採用カットも「試行の記録」として説明責任の対象になり得るため）

## 保存場所
- このプロジェクトフォルダ配下 `Prompt-Logs/` に月次ファイルで記録（例: `2026-08-プロンプトログ.md`）
- Obsidian Vault自体がGit管理下にあるため、記録後は**都度コミット**する（コミット日時が改ざんしにくいタイムスタンプ証跡になる）
- 参照画像・出力ファイルの実体は別途、案件専用の暗号化ストレージに保存し、ログには**ファイル名とSHA-256ハッシュのみ**を記載する（Vault自体に大容量メディアを置かない）

## レコード項目（1行 = 1生成ジョブ）

| 項目 | 説明 |
|---|---|
| 日時 | 実行日時 |
| ツール/モデル/バージョン | 例: `Runway Gen-4`, `Adobe Firefly Video v3` |
| プロンプト | ポジティブ/ネガティブプロンプト全文 |
| パラメータ | seed, 尺, 解像度, 参照画像の有無等 |
| 入力素材ハッシュ | 参照画像・音声のSHA-256（該当する場合） |
| 出力ファイル名 | |
| 出力ハッシュ | 出力ファイルのSHA-256 |
| 用途/シーン | カット番号・シーン名 |
| 採否 | 採用/不採用 |
| 備考 | 人間による編集・演出の関与内容など |

## ハッシュ取得コマンド例

```bash
# macOS / Linux
shasum -a 256 output.mp4

# Windows PowerShell
Get-FileHash output.mp4 -Algorithm SHA256
```

## テンプレート（月次ファイルの先頭にコピーして使う）

```markdown
# YYYY-MM プロンプトログ

## YYYY-MM-DD

### レコード1
- ツール/モデル: 
- プロンプト: 
- パラメータ: 
- 入力素材ハッシュ: 
- 出力ファイル名: 
- 出力ハッシュ: 
- 用途/シーン: 
- 採否: 
- 備考: 
```

## Claude等LLMを併用する場合の補足
- Team/Enterprise管理コンソールに利用ログ機能がある場合は、そちらも証跡として保持する（エクスポート機能があればPDF/CSVで定期保存）
- 自己記録と管理コンソールのログの**二重化**により、条件②（説明責任）の裏付けを強くする

## 保存期間
- クライアントとの契約で定める監査対応期間に合わせる（未定の場合は最低3年を目安に、契約書へ明記する）
- 契約終了時の削除タイミング・方法もクライアントと事前合意する
