# AI動画制作 コンプライアンス環境構築ガイド

> 前提: 私（Claude）は法律の専門家ではありません。契約条項の最終文言や各AIサービスの現行規約は必ずクライアントの法務部門・自社の弁護士に確認してください。本ドキュメントは「何を確認し、何を整えればよいか」を洗い出した実務ガイドです。各社の利用規約・DPA（データ処理契約）は更新頻度が高いため、記載内容は**契約前に必ず最新版で再確認**すること。

## 0. 全体方針

個人クリエイターが大手企業と同等のガバナンス体制を単独で作るのは現実的に不可能です。狙うべきは以下の3点です。

1. **ツール選定でリスクを下げる**（Free/個人向けプランではなくBusiness/Enterprise/API契約を使う）
2. **自分側の記録・運用でカバーする**（ベンダー側にログ機能がなくても、自分でプロンプト・素材・出力を記録する）
3. **できないことは正直にクライアントへ開示する**（特に「AI提供元への監査」は個人が単独で保証できない領域）

以下、クライアント提示の5条件ごとに対応方針をまとめます。

---

## 1. 「LLMに学習されない設定」への対応

### 考え方
生成AIサービスは大きく2種類の立て付けがあります。

- **個人/無料プラン**: 既定で「入力内容をモデル改善に利用する」設定になっていることが多く、オプトアウト操作が必要な場合がある
- **Business/Enterprise/API契約**: 契約上、原則として顧客の入力・出力をモデルの追加学習に使わないことが多い（ベンダーの商用利用規約・DPAに明記されているのが一般的）

### やること
- [ ] 制作に使う全ツールを **Business/Team/Enterprise/API契約** に統一する（個人向けFree/Plus相当のプランは使わない）
- [ ] 各ツールの管理画面で「モデル改善のためのデータ利用」「Learn from your data」等のトグルが存在する場合は**明示的にOFF**にする
- [ ] OFFにした画面のスクリーンショットを日付入りで保存する（[[03-プロンプトログ運用ルール]]の証跡フォルダへ）
- [ ] 契約前にベンダーのサポート/営業窓口に「本アカウントの入力・出力はモデル学習に使用されないか」を**書面（メール）で確認**し、回答を保存する
- [ ] 動画生成AIには「コミュニティギャラリー」「公開フィード」に生成物を自動投稿する設定がある製品が多い（Runway/Pika/Kling等）。これも既定でONの場合があるため**必ずOFF**にする（学習目的の二次利用経路になり得るため、条件①・④の両方に関わる）

---

## 2. 「ログ取得・説明責任」への対応

### 考え方
クライアントも認めている通り、**ベンダー側のログ取得が不可能な場合は自己保存で代替**できます。個人制作の現実解として、ベンダー任せにせず**自前のログ基盤を持つ**方針にします。

### 記録すべき項目（1生成ジョブ = 1レコード）
| 項目 | 内容 |
|---|---|
| 日時 | 生成実行日時（YYYY-MM-DD HH:MM） |
| ツール/モデル/バージョン | 例: Runway Gen-4, Adobe Firefly Video v3 |
| プロンプト全文 | ポジティブ/ネガティブプロンプト、パラメータ（seed, 尺, 解像度, 参照画像等） |
| 入力素材 | 参照画像・音声等のファイル名とハッシュ値（SHA-256） |
| 出力ファイル | ファイル名とハッシュ値（SHA-256） |
| 実行者 | 自分の氏名/アカウント |
| 用途・シーン | どのカット/シーン用か、案件名 |
| 承認状況 | クライアント確認済みか |

具体的なテンプレートと保存フローは [[03-プロンプトログ運用ルール]] を参照。

### やること
- [ ] 上記スキーマでログを記録する仕組みを用意する（このVault内 `Prompt-Logs/` フォルダ、またはスプレッドシート）
- [ ] 出力ファイルはSHA-256ハッシュを取得し、ログに記録する（改ざん検知・納品物の同一性証明のため）
- [ ] ログファイルはGit管理下に置き、生成の都度コミットする（コミット履歴のタイムスタンプが「いつ・何を生成したか」の一種の証跡になる）
- [ ] LLM（Claude等）を台本・プロンプト設計に使う場合は、Team/Enterprise管理コンソールの利用ログ機能があれば併用する（自己記録の裏付けとして）

---

## 3. 「監査・調査対応」への対応 ※最も限界がある領域

### 正直な現状認識
「生成AI提供元から必要な情報開示を受ける」ことを**個人クリエイターが契約上ベンダーに義務付けるのは基本的に困難**です。これはエンタープライズ契約（多くの場合、法人単位・一定の契約規模）でDPAや監査条項を締結して初めて実効性を持つ領域であり、個人アカウントのBusinessプラン程度では「監査に応じる法的義務」までは通常含まれません。

### 現実的な代替策
- **第三者保証レポートの活用**: 主要ベンダーはSOC 2 Type II、ISO 27001、Trust Center/Trust Portal等の第三者監査結果を公開している場合が多い。有事の際に個別開示を求める代わりに、これらの公開資料を事前に収集し、クライアントに提示する
- **自己ログでの一次対応**: 条件②で構築したプロンプトログ・出力ハッシュ・素材保存があれば、「何を・いつ・どのツールで生成したか」は自分側の記録だけで説明責任の大部分を果たせる
- **契約書での責任範囲の明確化**: 「生成AI提供元の内部情報開示」は自分の努力義務ではなく、ベンダーの規約・契約形態に依存する旨をクライアントとの契約書に明記してもらう（後述の説明資料参照）
- **代理店/リセラー経由の検討**: どうしてもベンダーとの直接の監査契約が必要な規模の案件であれば、エンタープライズ契約を持つ代理店経由でのツール利用や、クライアント自身がベンダーと直接契約し、自分はそのアカウントの中で作業する形態も選択肢になる

### やること
- [ ] 使用予定の全ツールについて、公開されているSOC2/ISO27001/Trust Center資料の有無を確認し、リンク集を作る
- [ ] 「個人契約では担保できない範囲」をクライアントに事前開示し、書面で合意を得る（[[04-クライアント向け説明資料(ドラフト)]]参照）

---

## 4. 「生成AI提供者自身のサービス向上・利用に使われない」への対応

条件①と重なる部分が多いが、範囲がやや広い（学習データ利用だけでなく、広報・事例紹介・人手レビューへの利用も含む）。

### やること
- [ ] コミュニティ投稿・公開ギャラリー・「Feature this creation」等の共有系機能を全てOFFにする
- [ ] 各ツールの規約で「カスタマー事例として利用する場合は個別同意を得る」旨が明記されているか確認する
- [ ] Business/Enterprise契約では「Abuse monitoring（不正利用検知）」目的での一時的な人手レビューが規約上残ることが一般的。これは学習・サービス改善とは目的が異なるため、条件④の対象外として扱ってよいか、契約書上の文言をクライアントと事前にすり合わせる

---

## 5. 「生成物が自社利用範囲で使用できること」への対応

### 確認すべきポイント
- **出力の権利帰属**: 利用規約上、生成物の権利がユーザー（＝クライアント）に帰属することが明記されているか
- **商用利用可否**: Freeプランは非商用限定、Business/Enterpriseプランで商用利用可、という切り分けをしているベンダーが多いため、プラン選定時に必ず確認する
- **著作権侵害の補償（IP indemnification）**: 学習データが正規ライセンス/自社データのみである等を理由に、出力の著作権侵害クレームに対する補償を提供するベンダーもある。大手企業案件では特に重視されるポイントなので、補償の有無を比較材料に加える
- **日本の著作権法上の論点**: 完全にAI任せで生成した映像は「思想又は感情を創作的に表現したもの」（著作権法上の著作物）と認められない可能性があるという議論が文化庁の資料でも示されている。**人間による創作的関与（構成・編集・カット選択・演出指示等）を記録しておく**ことは、権利者としての立場を主張する上でも有効であり、条件②のプロンプトログがそのままこの証跡にもなる

### やること
- [ ] 使用予定ツールの利用規約から「生成物の権利帰属」条項を抜粋し一覧化する
- [ ] IP補償の有無を比較表に記載する（[[02-推奨AIツール一覧]]）
- [ ] 編集・構成・カット選択など、自分が創作的に関与した工程をログに残す（著作物性の担保）

---

## 6. 推奨する制作環境（全体構成）

```
[アカウント分離]
  クライアント案件専用のビジネスアカウント（Google Workspace等）を新規発行
  └─ 個人の他案件・プライベート利用とは完全に分離

[ツール層]  ※すべてBusiness/Team/Enterprise or API契約
  台本・プロンプト設計: Claude (Team/Enterprise) など
  画像生成: Adobe Firefly (Enterprise) など
  動画生成: Runway/Google Veo(Vertex AI経由)/Adobe Firefly Video 等
              ※Enterprise/API契約のもの。個人向けFreeプランは不可
  音声・字幕: ElevenLabs (Business) 等
  最終編集: ローカル環境のNLE (Premiere Pro / DaVinci Resolve)
              → クラウドAI処理を経由しない最終工程はローカルで完結させ、露出面を減らす

[記録層]
  プロンプトログ（このVault Prompt-Logs/、Git管理）
  出力ハッシュ台帳
  規約・DPA・スクリーンショットのアーカイブ（日付付き）

[素材ストレージ]
  案件専用の暗号化ドライブ / アクセス制限付きクラウドフォルダ
  契約終了後の削除ポリシーをクライアントと事前合意
```

## 7. 契約・書面で確認すべきこと（チェックリスト）

- [ ] 各ツールの現行版ToS/DPA（契約時点の日付でPDF保存）
- [ ] 「モデル学習への不使用」の明文規定 or 個別合意メール
- [ ] 「商用利用可」「生成物の権利帰属」の明文規定
- [ ] IP侵害補償条項の有無
- [ ] SOC2/ISO27001/Trust Center等の第三者保証資料
- [ ] データ保持期間・削除ポリシー
- [ ] コミュニティ投稿等のオプトアウト設定手順

## 8. クライアントに事前に伝えておくべきこと

詳細は [[04-クライアント向け説明資料(ドラフト)]] にまとめるが、要点は以下:

1. 対応するツールの一覧とプラン（Business/Enterprise/API契約であること）
2. プロンプト・素材・出力の自己記録運用の内容と保存期間
3. **「生成AI提供元への監査対応」は個人契約の範囲では保証できない**こと、代替として第三者保証資料の提示で対応する旨
4. 生成物の権利帰属・商用利用可否の根拠（規約の該当箇所）
5. 人間の創作的関与（編集・構成）を記録している旨（著作物性の担保）

## 9. 運用開始後のルーティン

- 生成のたびに [[03-プロンプトログ運用ルール]] に従いログを記録
- 月次でツール規約の変更有無を確認（規約改定の通知を購読）
- 案件終了時に素材・ログをアーカイブし、削除ポリシーに従って処理
