# MiniMax H3 運用ガイド

> 調査時点: 2026年9月。仕様は更新されるので、大きな案件の前は一次情報を確認すること。
> コスト面の判断は [[00-結論とロードマップ]] にまとめてある。

---

## モデルの基本仕様

| 項目 | 内容 |
|---|---|
| 種別 | マルチモーダル動画生成(映像+音声を同時生成) |
| 公開形態 | **オープンウェイト**(ダウンロードして自分で実行できる) |
| モデルサイズ | 42.5GB |
| 枝刈り+int8版 | 31.7GB ← 32GB VRAMに収まる |
| 出力解像度 | **768pベース**(API版の2Kはオープンウェイトに含まれない) |
| 生成尺 | 4〜15秒 |
| 入力モード | T2VA / I2VA / FL2VA / L2VA / Ref2VA |

### 入力モードの使い分け

| モード | 入力 | 使いどころ |
|---|---|---|
| **T2VA** | テキストのみ | ゼロから作る。キャラの一貫性は保ちにくい |
| **I2VA** | 最初のフレーム画像 | ⭐ **キャラものの基本**。絵柄を固定できる |
| **FL2VA** | 最初+最後のフレーム | 動きの着地点を決めたいとき。崩れ防止に有効 |
| **L2VA** | 最後のフレームのみ | 決めカットに向かって収束させたいとき |
| **Ref2VA** | 複数の参照(画像/動画/音声) | 複数キャラ・複数素材を統合するとき |

> 💡 プロンプトの書き方は `.claude/skills/h3-prompt-writing/` のスキルに
> 詳細な構造(`integrated_multimodal_description` / `overall_soundscape` /
> `non_diegetic_music`)が定義されている。**必ずそれに従って書くこと。**

## ハードウェア要件

| VRAM | 実用度 |
|---|---|
| 8GB | GGUF/int4で小さい画面のみ。実用は厳しい |
| 12GB | 最低ライン。5秒768pで6〜25分 |
| **24GB** | 推奨ライン。枝刈りint8が乗る |
| **32GB** | ⭐ 快適。10秒864×480で**175秒** |
| 48GB以上 | 量子化を弱められる。画質重視ならここ |
| 80GB | **この用途には過剰** |

**システムRAM: 64GB以上、できれば128GB。** VRAMに乗らない分をここに逃がすため、
ここが細いとGPUが待たされる。

## 運用ノウハウ

### キャラクターの一貫性を守る(いちばん大事)

`01-characters/character-reference.md` の制約を**毎回プロンプトに明示的に書く**。
「前も書いたから」では守られない。特に効いている書き方:

- **禁止事項を肯定文で断言する**
  ×「眉毛をつけないでください」
  ○「その顔はどの瞬間も、丸い点目と輪郭線だけの口のみで構成される」
- **物理の挙動を言葉で縛る**
  「接触点でやわらかくくぼむが、平らになったり丸みを失ったりすることはない」
- **上限を数値で与える**
  「口の開き幅は顔の横幅の3分の1程度まで」
- **透明素材は「透けて見える」まで書く**
  「口の中には色も陰影も塗りも一切なく、後ろのガムボールが透けて見える」

### 崩れたときの立て直し方

顔が崩れたショットの続きを作るときは、**崩れた最終フレームを使わない**。
「理想画質」の正しい参照画像に戻してから I2VA で作り直す。
`C2a` `C3a` でこの手を使っているのが、そのまま正解の型。

### ショット分割は使わない

`[Shot 2]` などの追加ショット表記は使わず、**`[Shot 1]` だけで最初から最後まで
記述する**。分割すると被写体の同一性が崩れやすい。

### 生成結果を「間違い」で捨てない

`C-2d` v1 では、意図より強く当たった結果が「可愛かった」ので、
**v2でその強さを採用する**という判断をしている。これは非常に良い運用。
AIの出した偶然を演出に取り込めるのは、人がディレクションしている証拠。
**判定は OK/NG の二択にせず、メモに「何が良かったか」を必ず書く。**
